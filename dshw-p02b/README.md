# P02b：CSMAR 上市公司财务特征清洗与分析

## 数据来源

- **数据库**：CSMAR（国泰安）
- **原始文件位置**：`data/data_raw_zip/`（7 个 .zip 文件）
- **解压后文件位置**：`data/raw/`（按来源分子目录存放）

## 数据清洗说明

- **样本筛选规则**：A 股上市公司，会计年度 >= 2000，合并报表口径（CSMAR 跨表查询 `FS_Combas` 前缀即为合并报表）。金融业（J）保留。
- **主键统一**：股票代码统一为 6 位字符串（`code`），前导零补齐；会计年度统一为整数（`year`），兼容 `YYYY` 和 `YYYY-MM-DD` 两种日期格式。
- **重复值处理规则**：同一 `code-year` 若存在多个观测（如资产负债表与利润表拼接产生的重复），保留缺失值最少的记录。
- **缺失值处理规则**：统计各变量缺失数量和比例（见 `output/tables/missing_summary.csv`），不进行插补。分母 <= 0（负资产、负权益等）导致比率无法计算时，对应比率设为缺失。
- **离群值处理规则**：对 Lev, SL, LL, SDR, Cash, ROA, ROE, SLoan, LLoan, HHI5 按年度在 1% 和 99% 分位数缩尾（winsorize）。Size、Top1 和 Age 不做缩尾。同时保留原始变量（`_raw` 后缀）和缩尾后变量（无后缀）。缩尾前后对比见 `output/tables/winsor_summary.csv`。
- **合并规则**：以 `code-year` 为主键，资产负债表为基础表，依次 left join 利润表、股权结构、公司信息。每次合并前后记录行数变化。

## 存储方式

### 基础：CSV

所有清洗后的核心数据保存为 CSV 格式：
- `data/clean/firm_year_clean.csv` — 清洗后的单表数据
- `data/combined/csmar_firm_year_panel.csv` — 合并后的分析数据（31.9 MB, 145,825 行 × 28 列）

**CSV 的优点**：通用性强，任何软件（Excel、Stata、R、Python）均可直接读取；纯文本格式便于版本控制（`git diff` 可追踪数据变更）；人类可读，便于快速检查数据内容。

**CSV 的不足**：无数据类型元信息（每次读取需重新推断或指定 dtype）；无内置压缩（145k 行已产生 32 MB，扩展到全部 A 股季度数据将超过 500 MB）；行式存储不支持按列读取（读取 Lev 列也需加载全部 28 列）；浮点数精度可能因文本转换而有微小损失。

**为什么仍以 CSV 为基础格式**：本次作业数据量在十万行级别，CSV 完全满足需求；课程作业需确保教师和助教无论使用何种软件都能直接打开查看数据；文本格式符合学术研究对数据透明性和可复现性的要求。

### 进阶：Parquet

最终面板数据额外保存为 Parquet 格式：
- `data/combined/csmar_firm_year_panel.parquet`（13.3 MB，压缩比 2.4×）

选择 Parquet 的理由：
1. **列式存储**：可按需读取特定列（如只读 code, year, Lev, ROA），大幅减少内存占用和 I/O 时间。在本次数据中，读取 5 列比读取全部 28 列快约 76 倍
2. **内置压缩**：文件体积比 CSV 缩小 2.4 倍（32 MB → 13 MB）
3. **保留数据类型 Schema**：无需每次重新推断 dtype，避免股票代码被读成整数等问题
4. **扩展性**：若扩展到全部 A 股（~5500 家）× 季度（×4）× 多数据库合并，Parquet 的列式存储和谓词下推优势会更加显著——读取速度差距可能扩大到 100 倍以上

## 如何运行

1. 安装依赖：
   ```bash
   pip install -r requirements.txt
   ```
2. 将 `CSMAR.zip` 放置于项目根目录

   ```bash
   jupyter nbconvert --to html 03_analysis.ipynb --output report.html
   ```
